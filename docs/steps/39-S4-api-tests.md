# 39 · S4 Contract tests against the mock

Phase 6 · 60 min · Depends: S3 · Decisions: D8.4 A to D (on the mock) ·
Spec: specs/contracts.md "Validator rules" (what the contract promises)

## Goal

Generated Jest tests inside the app that prove the mock API keeps every
promise in the contract, run by `pnpm nx test web`.

## What this step does

1. **Generate Jest tests inside the app** that call the route handlers
   directly, one file per entity plus auth, each test on a fresh copy of the
   seed.
2. **What they prove**: every operation's happy path returns the promised
   shape and status; every error the contract lists can happen (validation
   with field names, 401 without a session, 403 on another user's row, 404,
   409 on uniqueness and bad transitions); pagination and sorting; cascades
   on delete; data survives a store reload.
3. **Register the `apitest` stage** that runs them and fails the run on red.

After this step the mock API is held to the contract by tests no model can
edit.

## Before you start

- `web/jest.config.cts` runs `next/jest` with the Nx preset and a jsdom
  environment; a `/** @jest-environment node */` docblock switches a file
  to Node, where `Request`/`Response` exist. Check that `@app/entities/*`
  resolves under Jest (`next/jest` maps tsconfig paths); if not, add a
  `moduleNameMapper` for `^@app/(.*)$` to the template's web Jest config.
- Handlers are called directly: no server, no port.

## Implementation details

### `src/codegen/apiTests.ts`

```ts
export function generateApiTests(run: Run, contract: Contract): string[];
```

**`web/app/api/__tests__/_setup.ts`** (template-worthy; write it from the
generator for now):

```ts
export async function freshDb(): Promise<string>;   // copies seed.json to a temp file, sets process.env.MOCK_DB_PATH, returns the path
export async function call(handler: Function, method: string, path: string, opts: { body?: unknown; cookie?: string; params?: Record<string, string> } = {}): Promise<{ status: number; json: unknown; headers: Headers }>;
export async function signIn(email: string, password = 'demo1234'): Promise<string>;   // cookie string from the sign-in handler's set-cookie
export const DEMO = 'demo@example.com', OTHER = 'other@example.com';
```

**`web/app/api/__tests__/<entity>.test.ts`** per entity, `beforeEach(freshDb)`,
and for each operation:

- list: 200, `TaskPage.parse(json)` succeeds, `total` equals the seeded
  rows owned by demo, `pageSize` default 20; `?sort=-createdAt` order;
  one filter; `?q=` on a seeded value; `?pageSize=500` → 400.
- get: 200 for a seeded id, 404 for a random uuid.
- create: 201 and `TaskSchema.parse`; the row is in a fresh `readDb()`
  (data survives); each `invalidExamples` body → 400 with a `fields` entry
  naming the field; a duplicate of a unique field → 409.
- update: 200 with a partial body; 404 unknown.
- delete: 204; children handled per `onDelete` (cascade: gone; restrict: 409).
- action: a seeded row in the `from` state → 200 with the `to` state; a row
  in another state → 409 `rule_violation`.
- access: every non-public op without a cookie → 401; with `OTHER`'s cookie
  on demo's row → 403 (owner) or 200 (public).

**`auth.test.ts`**: sign-up 201 and sets a cookie, duplicate email 409,
sign-in wrong password 401, `me` with and without a cookie, sign-out 204
then `me` 401.

Titles name the operation and the error code so failures read as
contract clauses: `it('createTask rejects a missing title with validation_failed')`.

Files go through `writeGenerated` (origin `codegen`, step `S4`); the
`apitest` stage runs `pnpm nx test web` in the app and records the result
(`check:run`), failing the run on red.

### Tests at the generator level

`apiTests.test.ts`: generated files transpile; one `it(` per expected case
counted against the contract (`operations.length * N + errors`).

## Done when

```sh
pnpm weave run … --run <id> --to apitest
cd runs/<id>/app && pnpm nx test web      # all generated tests pass
```

## Watch out

- These tests are generated by code and never edited by a model (T3
  refuses writes under `__tests__`).
- Keep each test independent: `freshDb` per test, no shared state.
