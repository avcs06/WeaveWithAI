# 55 · T1 Playwright tests from the frozen flows

Phase 9 · 2 h · Depends: R6, FE2 · Decisions: D8.1 A, D8.2 A, D7.3 C ·
Spec: specs/flows.md "Schema" (steps, fields, alternatives); specs/reconciliation.md
"Coverage matrix" (which screen and nodes serve a step)

## Goal

One Playwright spec per flow, generated by code from the frozen flows,
the screens and the coverage matrix, with the model only turning the
flow's outcomes into assertions. Tests exist before the frontend is
finished and never drift toward it.

## What this step does

1. **Playwright is added to the template** with a config that starts the dev
   server on its own seeded store, plus shared fixtures (reset, sign in, fill
   a field by label, force an API failure).
2. **Code generates one spec per flow** from the frozen flows and the
   coverage matrix: for each step, the action on the serving node (by role
   and name, falling back to the node's test id), the fields filled with the
   flow's example values; for each alternative, the matching setup (empty
   field, forced failure, a user with no data, a random id, cancel).
3. **The model's only job is the assertions**: one structured call per flow
   turns each step's "what the website shows" into a checkable expectation;
   code renders them.
4. **Tests exist before the frontend is finished**, so they can't drift
   toward whatever was built; the loop refuses to let a model edit them.

After this step every flow has an executable acceptance test.

## Before you start

- The template pins `playwright-core@1.56.1`; `@playwright/test` must match
  the browser build: add `@playwright/test@1.56.1` to the template's
  devDependencies, a `playwright.config.ts` at the template root and a
  `test:e2e` script (template change).
- The mock API resets through `POST /api/_mock/reset` (step 38) and takes
  `x-mock-fail: <code>` to force an error; `server_error` maps to 500.
- Locators: role and label first, `data-testid={node.id}` as the fallback
  (D7.3 C); every node root has the testid (step 42 and 44).

## Implementation details

### 1. Template files

`playwright.config.ts`:

```ts
import { defineConfig } from '@playwright/test';
export default defineConfig({
  testDir: 'web/e2e', fullyParallel: false, workers: 1, retries: 0,
  use: { baseURL: 'http://localhost:3001', trace: 'retain-on-failure', screenshot: 'only-on-failure' },
  webServer: { command: 'pnpm dev', url: 'http://localhost:3001', reuseExistingServer: true, env: { MOCK_DB_PATH: 'web/mocks/e2e-db.json', MOCK_LATENCY_MS: '0' } },
});
```

`web/e2e/fixtures.ts`: `test.extend` with `resetDb()` (POST reset),
`signIn(email, password)` (API request to sign-in, cookie into the
context), `signInAsOther()`, `fillField(page, label, value, kind)` (text
inputs by label; the DS `Select` by opening the trigger and choosing the
option text; checkbox by label), `forceFailure(page, code)` (`page.route`
adding the `x-mock-fail` header to `/api/**` requests), `expectError(page,
text?)`.

Scripts: `"test:e2e": "playwright test"`. Run `pnpm exec playwright install
chromium` is not needed when the browser build matches `playwright-core`'s.

### 2. `src/stages/tests/generate.ts`

```ts
export async function generateE2e(ctx: StageContext, lock: Lock): Promise<string[]>;
export function specFor(flow: Flow, plan: FlowPlan, assertions: Assertions): string;   // pure: the spec file text
export function planFlow(flow: Flow, matrix: Matrix, screens: Screens, contract: Contract): FlowPlan;   // which screen, nodes, inputs and operations serve each step
```

Spec shape (`web/e2e/<F03>-<slug>.spec.ts`):

```ts
import { test, expect } from './fixtures';
test.describe('F03 Add a task', () => {
  test.beforeEach(async ({ page, resetDb, signIn }) => { await resetDb(); await signIn('demo@example.com'); await page.goto('/projects/<seeded id>'); });
  test('F03 happy path', async ({ page, fillField }) => {
    // F03.S01 user: opens the task form
    await page.getByRole('button', { name: 'Add task' }).or(page.getByTestId('S04.n05')).click();
    // F03.S02 user: fills in and saves
    await fillField(page, 'Title', 'Write the report', 'text');
    await fillField(page, 'Priority', 'High', 'singleChoice');
    await page.getByRole('button', { name: 'Save' }).or(page.getByTestId('S05.n09')).click();
    await expect(page.getByText('Write the report')).toBeVisible();   // assertion from the model: websiteResponse of F03.S02
  });
  test('F03.A01 invalid: empty title', …);     // submit without the required field; expect the field error (assertion)
  test('F03.A02 failure: saving fails', …);    // forceFailure(page, 'server_error') before submit; values kept; retry offered (assertion)
  test('F03.A03 cancel', …);
});
```

Rules of generation: entry route = the entry screen of the first step's
serving screen, or the sign-in page for auth flows; values from
`Field.example`, choice values from `options[0]`; `empty` alternatives run
as the other user; `confirm`/`cancel` click the dialog's confirm or cancel
button by role; `denied` signs in as a role without access when one
exists, else is skipped with `test.skip` and a reason; `notFound` visits a
random uuid. System steps wait for their `websiteResponse` assertion.

Assertions from the model: one structured call per flow with
`{ assertions: [{ after: 'F03.S02' | 'F03.A01', kind: 'visibleText' | 'visibleTestId' | 'urlContains' | 'countAtLeast' | 'notVisibleText', value: string, testId: string }] }`;
input = the flow, the serving screens' node texts and testids; validator:
`after` ids exist, testids exist on the serving screens, values non-empty.
Code renders each into the matching `expect`.

Files through `writeGenerated` (origin `codegen`, step `T1`; the `e2e`
stage registered here runs generation only; step 56 runs the specs).

### 3. Tests

`generate.test.ts` with a fake model and the golden freelancer workspace: one
spec per flow; each transpiles; the invalid-alternative test exists for
every flow with a form; `test.skip` appears only for `denied` without a
second role.

## Done when

```sh
pnpm weave run … --run <id> --to e2e
cd runs/<id>/app && pnpm exec playwright test --list     # lists one describe per flow
```

## Watch out

- Specs are never edited by a model (the loop denies `web/e2e/**`).
- `workers: 1` because every test shares one JSON store.
